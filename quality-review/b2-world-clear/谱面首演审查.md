## 2. WorldBossChart 合法内容来源提案

## 4. T6 ChartRef 与 VERDICT-030 兼容提案

建议 ChartRef 增加可选用途判别 `state?: 'Entry' | 'PremiereCompleted'`。可选仅服务已存在的无字段记录；新写入必须给出明确用途。

| 情况 | 处理提案 |
| --- | --- |
| 新 T6 终点事件 | 保留原 eventId、零向量、时间、来源、章节、目标 chartId、恰一次追加、DeepTrace 标记与揭示门控，仅在 ChartRef 加 `state:'Entry'`。 |
| 新 T7 / World 完成事件 | 仅在真实 ChartPremiere 返回完成事实后追加 `state:'PremiereCompleted'`。World 还须验证 chartId/tier=World、所授入口及 Primary 身份。 |
| ChartRef.state=Entry | 是目标引用，不是首演完成引用；不生成重玩首演事实、WorldClearRecord、账号里程碑。 |
| ChartRef.state=PremiereCompleted | 是明确完成引用；需要正常账本与身份验证，不接受仅由外部 JSON 标签构造的账号通关。 |
| 无 state 的精确已知 T6 历史形状 | 只读分类为 Entry，不重写旧事件。 |
| 无 state 的精确已知 T7 历史形状 | 只读分类为 PremiereCompleted；此分类不自动补写世界通关或账号事实。 |
| 其他无 state、未知字段值、形状矛盾、不可验证历史记录 | 分类 Unknown，显式诊断；不默认视为完成，不扫描 chartId 前缀猜测用途，不补字段，不触发账号写入。 |

“精确已知形状”至少包括：完整合法 NarrativeEvent、VectorSchemaVersion=1、全部 20 个向量分量为零、InputSource.Player、合法 AppendedAt、空 ChapterTag、旧 ChartRef 仅有 chartId；eventId 必须逐字为 `T6_ENDPOINT_PLACEHOLDER` 或 `T7_COMPLETION_PLACEHOLDER`。T7 还需非空且不是 `CHART_NOT_BOUND` 的 chartId，并在使用时与已验证的绑定谱面匹配。T6 的 `CHART_NOT_BOUND` 只能分类为未解析入口，绝不能升级为完成。

这是当前已知生产形状的保守兼容提案，不是通用历史存档恢复器。B2.2b 没有成功恢复通道，本批不得据此引入完整 hydration 或把任意未知 JSON 变成受信账本。即便历史 T7 被只读识别为完成，缺少当时的 World tier、Primary/worldId/主角和权威坐标证据时，也不生成 WorldClearRecord。

扩展点限于 constants.ChartRef 类型与 director 的事件构造/只读用途判据；不删除 T6 ChartRef、不改 NarrativeEvent 的既有必填结构、不改旧事件字节、不调整解谜、计时、得分或退出。`Unknown` 是诊断分类，不是新的 ChartRef 可写状态。
