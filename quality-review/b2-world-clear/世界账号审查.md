## 现有账号适配器与合法调用链提案

当前 `src/presentation/AccountMilestoneStorage.ts:1` 仅从 IntentPort 类型窄口导入投影；`:7` readProjection 严格读取；`:19` saveProjection 是适配器入口；`:22` 重读实际 current；`:24` 拒绝 true→false；`:27` 检查 current 与 expected；`:31` 执行单 key setItem；`:34` 使用独立 key `neurou-account-first-world-cleared-v1:`。这些逻辑无需修改。

`src/director/AccountMilestone.ts:25` 缺失投影读取为 false；`:27` 只读派生 `CopyPermission === FirstWorldCleared`；`:29` 发布冻结快照。`assets/scripts/WorldFolderBuilder.ts:74` 当前目录 reader 每次通过适配器重新读取；`src/presentation/WorldFolderView.ts:176` 读取快照并在 `:177` 展示权限，`:178` / `:179` 写只读 UI data。生产检索尚无生成真实世界通关投影的调用者；本报告也未新增调用者。

恢复实施后建议采用以下调用链：

1. 组合根装配 runtime 身份、同一权威账本读写源、WorldBossChart 合法内容，以及记录/投影持久化回调。
2. director 在成功的 Player 追加边界计算主角真实账本坐标并判定 SphereCrossing，发布 SphereCrossing 来源的 ChartEntry。
3. 玩家从该入口完成已校验的 WorldBossChart；director 根据真实 `Completed` / `completed=true` 完成事实识别首演，退出/暂停/超时均不能代用。
4. director 从**通关完成那一刻**的权威主角账本坐标冻结 RouteSignature 和 WorldClearRecord，绑定 accountId、worldId、characterId、chartId 与首演完成事实。
5. director 调用组合根注入的持久化回调；组合根先保存不可变账号通关记录，再调用现有 `AccountMilestoneStorage.saveProjection` 写 `FirstWorldCleared=true`。只有保存成功后，发布账号写入成功的产品反馈。
6. 当前页面与返回目录均重新经现有 Reader 读取；CopyPermission 自动派生 true。产品 UI 不发送“设为通关”或“授予权限”意图。

记录与路线属于账号层，独立于目录与 WorldStateStorage；删世界仅写墓碑，不能删除或改写账号通关事实。projection 保存字段继续严格只有 schemaVersion / accountId / FirstWorldCleared，不携带 CopyPermission、路线或记录列表。

## 记录先行与恢复对账提案

`quality-review/b2-foundation/VERDICT-211-225.md:25`（VERDICT-216）已经把真实写入权威与多 key 一致性协议留给 B2.2c；`:55` 明确现有 current / expected 检查不宣称跨 tab 原子 compare-and-swap 或多 key 事务。因此不能把现有 saveProjection 的成功检查说成 WorldClearRecord 与投影原子提交。

建议冻结如下最小可恢复协议，不修改适配器核心：

| 状态/失败点 | 要求 |
| --- | --- |
| 完成事实尚未产生 | 不创建 WorldClearRecord，不调用 saveProjection。 |
| 生成完成候选 | 将首演事实和完成时 RouteSignature 冻结；后续重试使用同一候选，不因当前坐标变化重新采样。 |
| 记录保存失败 | 不写 true 投影，不显示账号写入成功；在当前会话保留可重试候选，保留原始存储字节。 |
| 记录已保存，投影失败 | 保留已保存记录，显示明确待对账/保存失败；下一次登录或进入目录时，由可信编排校验该记录并重新读取 expected，再补写 true 投影。不得回滚记录或伪造一次新首演。 |
| 投影已 true | 同一世界同一首次通关的重复完成/重试不覆盖初次记录与路线；不重复调用 setItem。其他世界的新合法记录可以追加，账号事实仍 true。 |
| 陈旧 expected | 显式重新读取；若实际已 true，只完成对账；若损坏或身份不匹配，保留失败并不自动授权。 |
| 记录损坏、未知版本或账号/世界引用不匹配 | 保留原始数据、报告失败，不从布尔投影倒造通关记录，不随机重建路线。 |
| 旧合法 true 投影但缺少记录 | 保留 B2.2a 现有读取行为；标明记录缺失，不宣称已补齐历史生产通关证据。不得为了兼容改动 Reader 核心。 |

可新增独立账号记录存储适配器及 director coordinator。建议记录幂等键包含 accountId + worldId，保证“每世界第一次合法通关记录不可变”；chartId/完成事实引用用于校验，不以得分判断通关。接口具体名称与公开字段应在主任务裁定书/v3.8 附录提案冻结。

上述只解决账号事实与里程碑投影之间的恢复对账。它不宣称保存了完整 gameplay 世界快照，不进行账本、入口或进行中演奏的 hydration，也不改变 B2.2d 延后。多页面写入若需并发保证，必须限定单 writer 或使用明确互斥机制；不能声称 localStorage 的两次 setItem 自带事务。本轮没有实施或验证这个提案。
