## 后续需单独授权 / 裁定的功能

1. **RGB 波表工作区**：共享同一音乐工程与历史，但本批没有波表创作、RGB→音色/均匀度/亮度质感、谐波预设、手绘、鼓音色或效果器 UI。后续需定义 WavetableDefinition、资产引用及 schema 演进，不能直接向严格 schema1 加未知字段。
2. **网格工作区**：本批只有音符的显式 GuidancePosition / UV 元数据，未交付网格结构编辑、音阶映射、行中心音量映射或键位映射配置。后续需裁定 GridDefinition 与映射版本，保持内容坐标/网格坐标分离，不改变既有 gameplay 键盘布局或判定。
3. **特殊颜色效果语义**：ColorMusic TypeScript 的亮/暗自动效果用 else-if、并列时 R 优先；Java 效果槽允许并列通道同时触发。两者不可静默合并。未来实现此功能前提交 PROTOCOL；本批延期不选择其中任一套。
4. **真实音轨与标准 MIDI 文件**：当前导入/下载的是音乐项目 JSON、含历史草稿 JSON、ChartSourceData JSON；没有标准 `.mid` / SMF 导入导出、MIDI 设备录入、录音、音频片段裁剪/拼接/混音、真实 PCM min/max 波形或成品音频文件导出。MIDI 在本批表示音高/力度/tick 创作与源契约来源，不能据此声称已有二进制 MIDI 文件支持。
5. **音频引擎与采样**：不移植 AudioTrack、实时 DSP、完整 WebSynth、JNI 或 Android 解码线程。未来鼓 WAV 资产若进入交付，按具体资产保留来源与许可映射；29×256 鼓预览点不是真实鼓采样。

## 当前实现的容量与试听边界

- 简易试听使用固定正弦音色，44.1 kHz 单声道离线生成 PCM，再由一个 AudioBufferSourceNode 播放；轨道 RGB / 显式位置不改变该音色。其用途是确认音高、时值、力度与时间编排，不代表 RGB 音色、完整乐器合成或音乐成品混音。
- 一次试听的媒体时长须 **大于 0 且不超过 10 分钟**。所有音符累计 `max(0, endTimeMs−timeMs) / 1000 × 44100` 的 note-frame 工作量须 **不超过 80,000,000**；重叠音符分别累计。超限显式拒绝试听，保留音乐草稿；不静默丢音或截断导出。
- 音乐项目的 `durationTicks` 限制为 **不超过 PPQ×4096**；UI 网格/标尺按视口宽度采样。音乐工程可通过项目校验而超出上述试听容量，项目保存与源导出不等同于保证其可在本批试听器中播放。
- 当前 UI 的“应用 BPM”是将 tempoMap 改为 tick0 的单一 BPM 事务；撤销可恢复原分段 tempoMap。项目 JSON 支持分段 tempo 数据与轨道 offset，UI 没有完整的 tempo 曲线编辑工作区。
- 引导线发布还要求每线至少两个真实事件、合法键位和有效路径；首刻和弦/同刻不同位置等不兼容组合会提示拆线或修改映射。允许保存不完整创作草稿，拒绝发布不兼容数据，不补造音乐事件。

这些限制是本批最小交付范围，后续扩容或加入新创作能力需在对应裁定与验收中明确。

## 验证范围与待人工确认

自动验证覆盖冻结输入链、历史恢复、时间转换、真实消费者 schema3、PCM 数据及播放状态、双分辨率 Creator 交互与生命周期等，具体以最终验收附件为准。**本批没有完成人工听感验收**：不能从 AudioContext.running、非零 PCM 或播放截图推断设备实际声量、音色主观质量、扬声器/耳机输出和端到端听觉延迟均已人工确认。需要用户在实际输出设备点击播放试听确认；这不影响已完成的逻辑、文件和界面证据本身。

现有依赖门禁使用 regex 解析，不能完整覆盖所有 TypeScript / CommonJS 导入写法。只读负测发现普通 `require('../editor/...')` 和 side-effect `import '../editor/...'` 不进入既有静态依赖 parser。该解析范围属于既有检查器限制；本批按授权不扩张原 parser，且**新增实际代码图已另用 TypeScript AST 审计**：7 个新 TS 文件没有 require / side-effect import，逻辑零 cc/禁域依赖，musicEditor→editor 与 presentation→musicEditor/editor 为整句 type import。依据见 [independent-review-results.json](D:/Project/A_New_Begin/Neurou_official/quality-review/music-editor/independent-review-results.json)。未来新增上述导入写法时，不能仅用 gate 零错误代替矩阵审查。

`sourceRevision` 由编辑 revision 加规范工程快照的双 32 位校验和组成，用于区分常见的同 ID / 同 revision 不同导入内容。它**不是密码学摘要、签名、真实性证明或抗碰撞安全标识**；不用于权限、账本认证或跨设备信任判定。若后续共享工程需要这些能力，应另定版本/签名机制，不扩大本字段语义。
