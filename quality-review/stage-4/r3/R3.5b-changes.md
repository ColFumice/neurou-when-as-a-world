## 2. R2 `ChartSourceData v2` 复用说明

先查了现有代码，结论是**没有可直接 import 的 R2 v2 实现**：

- `v4/core` 下没有 `ChartSourceData` / `parseChartSourceData`。
- `quality-review/stage-4/r3/R3.5-plan.md:31` 明确写着：`ChartSourceData v2` “仅 docs/spec/stage-4.md §4.4 有文字，无代码；先落类型 + 严格 parser”。
- 仓库里的 `src/editor/GuidanceEditorSession.ts:19` 是 **v1**：`schemaVersion: 1`、`sourceId`、`events`，且 parser 需要 `KeyboardPadLayout`；不能直接当 v2 用。
- 因此本轮没有复制 legacy v1，也没有第二份 v2。`v4/core/editor/ChartSourceData.ts` 是当前唯一 v2 实现，字段按 R2 v2 契约（`chartId / provenance / layers / notes`）落。
- 如果 R2 分支后续提供同构 v2，R3.5c 接线时应改为从该文件 re-export，并删除本地 parser，避免两份漂移。

`ChartSourceData` v2 关键规则：

- 只接受 `schemaVersion: 2`；v1 抛 `UnsupportedSchemaVersion`。
- 顶层/notes 严格白名单，未知字段拒绝。
- `layers` 从 1 连续；第 1 层 TopMost；第 2 层 Grid；第 3+ 层 FullScreen（`fullScreenInput` 可选）。
- notes 按 `timeMs → layer → grid → pad` 稳定排序并冻结。
- 不包含 logo、keyframeId、trackId、selection 等 UI/编辑状态。

- `timeMs = viewStart + (x - laneLeft) / pxPerMs`；`x = laneLeft + (timeMs - viewStart) * pxPerMs`。

- 拖动期间 `lockViewport`；zoom/scroll 为 no-op，playhead 仍可更新。

## 4. 时间轴映射、吸附、换轨

### 4.1 映射

```text
timeMs = viewStartMs + (x - laneLeft) / pxPerMs
x      = laneLeft + (timeMs - viewStartMs) * pxPerMs
viewEndMs = viewStartMs + laneWidth / pxPerMs
```

只存 `viewStartMs / pxPerMs / laneWidth`；`viewEndMs` 派生，避免三份状态互相打架。

### 4.2 两段式拖拽

- `beginKeyframeDrag` → `phase=Pressed`；记录原 time/layer/pointer/playhead；`timeline.lockViewport()`；不写历史。
- `updateKeyframeDrag`：
  - 总位移 `<= 3px` → 保持 `phase=Pressed`、`changed=false`，并把 preview 重置为 original（防止“拖远再回来”提交旧 preview）；
  - 超过 3px → `phase=Dragging`；
  - `Shift` → 时间锁原值；
  - 否则 `timeline.snap(timeAtX(x), { altKey, frameDurationMs })`；
  - `targetLayerIndex` 由 R3.5c 的 lane 命中测试传入；E 只在 `|dy| > 24px` 时换轨；
  - 同步 `timeline.setPlayhead`，只更新 preview，不写 track/history。
- `commitKeyframeDrag` → 有变化才调一次 `moveKeyframe`（内部 push 一条 undo）；无变化不记录。
- `cancelKeyframeDrag` → 恢复起始 playhead、解锁 viewport，不写历史。
- R3.5c 把 Esc / pointercancel / lostpointercapture / blur 接到 cancel；rAF 调 update。

### 4.3 吸附

- 优先级：`Alt` 关闭 → 视频帧边界 → 10ms 网格 → clamp。
- 帧边界用 `Math.round(frameIndex * frameDurationMs)` 再取整毫秒，避免 23.976fps 产生小数 timeMs。
- v2 原始 `timeMs` 走 `fromJson` 或 `snap:false`，不强制吸附；新增/拖动/Inspector 默认吸附。

### 4.4 换轨与层语义

- `|dy| > 24px` 才换轨；`Shift` 只锁时间，仍可纵向换轨。
- 第 1 层：`pad=TopMost`，`grid=null`。
- 第 2 层：`pad=Light`（默认），`grid=1`。
- 第 3+ 层：`pad=Light`，`grid=null`。
- 同层同时间允许多个 keyframe（和弦）；`ChartKeyframe.compare` 排序 `time → layer → id`，不合并、不覆盖。

## 5. 撤销栈设计

- `ChartEditUndo` 只维护有界数组 + cursor，不持有 track；应用 patch 的是 `EditorWorldFile`。
- 每次 add/move/update/delete/setLogo/removeLogo 最多 push 一条。
- 空操作（time/layer/logo 无变化）不 push。
- `push` 新编辑截断 redo；容量 100。
- 删除 keyframe 的 `before.keyframe` 带 logo，undo 恢复 keyframe 即恢复 logo。
- `undo/redo` 后 `dirty=true`；`markSaved()` 清 dirty；history 不持久化。
- Inspector 的 Enter/blur、滑块 pointerup 由 UI 合并成一次 `updateKeyframe`，E 层只保证一次调用最多一条历史。

## 6. Logo 确定性随机

- `LogoPositionPicker` 是 Idle/Picking 状态机：未 begin 时 commit 返回 null；commit 后归一化 `(stageX - rect.x) / rect.width`，clamp 0..1，并关闭 active。
- `LogoRandomPlacement.place(seed, keyframeId)`：
  1. `text = `${Math.trunc(seed)}|${keyframeId}``；
  2. 32-bit FNV-1a：`hash ^= charCodeAt; hash = Math.imul(hash, 0x01000193) >>> 0`；
  3. `mulberry32(hash)` 生成两个 `[0,1)`；
  4. 默认 bounds `0.15..0.85`，`x = minX + r1 * (maxX - minX)`，y 同理；
  5. 不调用 `Math.random`，同 seed + keyframeId 两次完全一致。
- 删除 keyframe 级联删除 logo；undo 的 before 快照含 logo，因此恢复。

```json
    "stageHeight": 720
  }
}
```

不写：

- `history`
- `dirty`
- `selection`
- `timeline` 的 viewStart/pxPerMs/playhead
- `canvas.selectedKeyframeId` / `canvas.logoPosition`
- `mode` / `aiGeneration`

按本轮授权，editor.json 用 `tracks + canvas` 表达文档；media 引用留 R3.5c。

### 7.2 v2 导出

- `exportV2()` 只由 keyframes 派生 `layers + notes`；不写 logo/keyframeId/trackId/documentId/selection。
- 导出后立刻用 `parseChartSourceData` 回读校验；失败抛错，不返回半成品。
- 第 1 层 TopMost；第 2 层 Grid；第 3+ 层 FullScreen(Pointer)。
- notes 排序与 v2 parser 一致。
