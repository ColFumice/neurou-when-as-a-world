## 1. Application.destroy 修改方案

### 根因

1. `app.destroy(true, { children: true })` 的 `removeView = true` 会从 DOM 移除 React 托管的 canvas；workspace 更新重挂载后，React 仍认为 canvas 在 DOM 中，导致新 app 无法显示（黑屏）。
2. Pixi 8 destroy 默认会连带销毁 stage 子节点的 texture/filter；fisheye filter 仍绑定 `TextureSource` 时触发：

```text
textureSource was destroyed while still bound to a shader
```

### 修复

cleanup 顺序：

1. `app.ticker.remove(update)`；
2. 递归解绑 filter：
   - `detachFilters(app.stage)` 设置 `filters = null`；
   - 递归所有 `PIXI.Container` 子节点；
3. 使用不销毁纹理、不移除 canvas 的 destroy：

```ts
app.destroy(false, {
  children: true,
  texture: false,
  textureSource: false,
});
```

4. `textureCache.clear()` 只丢引用，不 `destroy()`；
5. 双击空白后的 folder 创建仍延迟 760ms；`createFolderRef` 保存最新回调，避免 effect 闭包旧值；
6. async mount 的 `disposed` 分支同样用 `destroy(false, { texture:false, textureSource:false })`。

这一步修掉了：
- `textureSource destroyed` WebGL 崩溃；
- destroy 后 canvas 被移除导致的黑屏；
- 延迟 timer 被异常中断后新 folder 不出现。

## 2. 全屏放大动画

原来从屏幕中心直接铺开，且没有白色边框跟随。现改为：

- 选中节点当前状态：

```ts
const fromWidth = 190 * selected.container.scale.x;
const fromHeight = 112 * selected.container.scale.y;
zoomFrom = {
  x: selected.container.x - fromWidth / 2,
  y: selected.container.y - fromHeight / 2,
  width: fromWidth,
  height: fromHeight,
};
```

- 700ms 插值，`easeInOutQuad`：

```text
eased = p < 0.5 ? 2p² : 1 - (-2p + 2)² / 2
x = from.x + (0 - from.x) * eased
y = from.y + (0 - from.y) * eased
width = from.width + (stage.width - from.width) * eased
height = from.height + (stage.height - from.height) * eased
```

- 覆盖层仍是 Pixi `zoomSprite`，从选中方框矩形平滑扩到全屏；
- **白色边框 `zoomFrame` 与 zoomSprite 同步**，每帧重绘同尺寸圆角矩形描边，不在开始时铺满全屏；
- 放大期间隐藏被选中的原方框，避免双层重影；
- `zoomActive = true` 时 `VignetteEffect` 不渲染（DOM 层直接移除，不是降低透明度）；
- 退出 zoom（空白/其他节点/Folder）时隐藏 zoomSprite/zoomFrame，恢复暗角。

## 3. Folder 尺寸

`ProjectTreeLayout` 对 Folder 节点额外乘：

```ts
const sizeScale = node.kind === 'Folder' ? 0.65 : 1;
scale = clamp(perspective, 0.55, 1.5) * sizeScale;
```

- Folder 基础尺寸为 Project 的 **65%**；
- 3D 位置、RGB→XYZ、相机、游走、连线逻辑不变；
- Folder 仍不参与 1.5× 选中放大。
