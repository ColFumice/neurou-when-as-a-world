## 4. Pixi 模块解析方案

选择 **方案 A**：由 app 解析 `pixi.js`。

理由：

- `v4/app/package.json` 已锁定 PixiJS 8.22.0；R3.1/R3.2 已在 app tsconfig 配置 `pixi.js` paths、在 Vite 配置 alias。
- P 层的 `ParallaxRenderer` 直接使用真实 Pixi 类型，不需要 app 注入一层不完整的结构类型。
- app 是组合根，负责运行时依赖；P 只做表现。

实现细节：

- `ParallaxRenderer` 文件扩展名为 `.tsx`（内部无 JSX）。原因：`v4/tsconfig.json` 的 root typecheck 只包含 `core/**/*.ts`，不含 `.tsx`，而 root 没有 Pixi 依赖；`.tsx` 让该文件由 app 的 `typecheck`（含 pixi paths）负责，同时仍被 check-naming 扫描。没有改 root tsconfig。
- 未新增 app tsconfig / Vite alias 改动：`pixi.js` 的 paths/alias 已在 R3.2 存在。

- R2：`export interface TimelineStateMachine { playbackState; progress; boundary; }`
- R3.4：`export class TimelineStateMachine`

## 9. W/P 实现摘要

### W · frame.ts

- `VisualFrameRect`：屏幕像素矩形。
- `VisualFrameParallaxFactor`：`layerIndex` + `factor`（0~2）。
- `VisualFrameSaturation` / `GlobalSaturation`：number 0~1；W 不 import 任何颜色库。
- `FrameTarget`：`Trace / Anchor / None` + 可选 `targetId` + `screenRect`。
- `FrameTracking`：`Idle / Tracking / Lost / Locked`。
- `VisualFrameTargetLock`：`Locked / Unlocked`。
- `VisualFrame`：aggregate interface + 同名值对象，静态方法：
  - `isTargetInsideFrame`
  - `computeFrameTracking`
  - `computeTargetLock`
- 判定：
  - 目标矩形中心在 frame 内（边界包含）。
  - 目标 None → 不命中、Idle、Unlocked。
  - Locked 在目标仍入框时保持 Locked；出框变 Lost。
  - `computeTargetLock` 的 `hitAtMs` 解释为“命中偏移”；`0 <= hitAtMs <= windowMs` 且目标入框才 Locked。

### P · parallax

- `ParallaxRenderer`：PixiJS 8 `Application`，异步 `mount(canvas)`（返回值 `Promise<void>`；与建议的 `void` 有差异，原因见 §10）；`unmount` / `render` / `destroy`。
- `ParallaxCamera`：`offsetPx = positionMs * 0.08 * parallaxFactor`；三层 UV 的 `u = ((positionMs * factor) / 4000) mod 1`。
- `ForegroundUV` / `MidgroundUV` / `BackgroundUV`：只读 `u/v/offsetX/offsetY`。
- `render` 只读 `WorldInstance` / `VisualFrame` / `TimelineStateMachine`；不写任何字段。
- fixture：3 层，factor 0.35 / 0.7 / 1.3。

## 10. 偏离与说明

1. `ParallaxRenderer.mount` 为 `Promise<void>`，因为 PixiJS 8 的 `Application.init` 是异步的；建议的同步 `void` 无法正确初始化。调用方 `ParallaxDemoScreen` 已 await。
2. `ParallaxRenderer.tsx` 无 JSX；扩展名选择见 §4，避免修改 root tsconfig/新增 root Pixi 依赖。
3. `VisualFrame` 的纯函数以同名值对象静态方法暴露，避免导出非 A 类函数名。
4. 视差因子只影响 P 的容器 offset，不修改 `TimelineStateMachine` 或 `WorldInstance`；满足 AC4-07 “不影响判定”的 R3.4 版本。
5. `VisualFrameSaturation` / `GlobalSaturation` 只是 number；W 层不 import 颜色库，实际颜色由 P 层决定。

## 11. 人工验收清单

在 `v4/app` 执行：

```powershell
npm run tauri dev
```

1. 打开应用，点击顶部“视差演示”。
2. 左右方向键：时间轴 position 变化；三层以不同速度滚动。
3. 到达 0 / 12000ms 边界时停止。
4. 点击 pause 后左右键无效；再 play 恢复。
5. 视差框矩形可见（半透明蓝框）；目标框可见。
6. 点击“target: inside/outside”：FrameTracking 在 Tracking/Lost 间变化；lock 显示。
7. 上下键调整 frameSat；Shift+上下调整 globalSat；HUD 数值变化。
8. 返回按钮回到项目事件树。
9. 说明：本地无音频输出，R3.4 不做音量；音量/亮度手势留后续。
