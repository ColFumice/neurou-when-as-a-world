| 裁定 | 落地 |

## 2. 命令与调用面

### 2.1 移除单目命令

- `media_import` 不再出现在：
  - `src/lib.rs` 的 `invoke_handler`
  - `build.rs` 的 `APP_COMMANDS`
  - `capabilities/default.json`
  - 生成后的 `gen/schemas/*`
- Rust 内部 `import_media` 实现已删除，不再保留单目入口。
- D 层 `MediaImport` 类型保留（兼容既有类型引用），但不再有对应 Tauri command。

### 2.2 新命令 `media_import_stereo`

```rust
#[tauri::command]
pub async fn media_import_stereo(
    state: State<'_, ActiveProjectRoot>,
    lock: State<'_, MediaLock>,
    left_path: String,
    right_path: String,
) -> Result<MediaStereoImport, FsError>
```

Tauri 调用参数：

```json
{ "leftPath": "C:\\media\\left.mp4", "rightPath": "C:\\media\\right.mp4" }
```

返回：

```ts
interface MediaStereoImport {
  pair: {
    stereoPairId: string;
    leftAssetId: string;
    rightAssetId: string;
    audioAssetId: string;
    createdAt: number;
  };
  left: MediaSource;
  right: MediaSource;
  audio: MediaSource;
  deduped: boolean;
}
```

## 3. Rust 校验与安全

### 3.1 路径

左右两个输入都走 `paths::validate_source_path`：

- 必须绝对路径、存在、普通文件；
- 拒绝 NUL/换行、设备路径、`\\?\GLOBALROOT`、`\\?\UNC`；
- Windows 设备名（CON/NUL/COM1…）拒绝；
- Unix `/dev`、`/proc`、`/sys` 拒绝；
- 输入可在 project root 外（用户自由选择素材），读取交给 ffmpeg/ffprobe。

输出全部由 Rust 生成：

```text
media/stereo/<stereoPairId>/left.mp4
media/stereo/<stereoPairId>/right.mp4
media/stereo/<stereoPairId>/audio.wav
```

- `stereoPairId` 为 16 位 hex；
- `paths::stereo_rel` 只接受 `left.mp4` / `right.mp4` / `audio.wav`；
- 最终路径仍走 `resolve_media_output`，拒绝 `..`、绝对路径和 media 外路径；
- 不存在用户文件名拼接。

### 3.2 Q2 严格对齐

对两个源分别 `ffprobe`，然后：

```text
kind 必须是 Video
width/height 必须 > 0
left.width  == right.width
left.height == right.height
|left.durationMs - right.durationMs| <= 500
```

失败码：

- `StereoDurationMismatch`：超过 500ms；
- `StereoResolutionMismatch`：宽高不同；
- `UnsupportedMedia`：不是视频 / 分辨率 0 / 时长为 0。

所有校验都在创建输出和写 manifest 之前；失败时 manifest 字节不变，不留 `media/stereo/<id>` 目录。

### 3.3 文件大小

- 每个输入最多 4 GiB（与 R3.5a 的 Video 上限一致）；
- 超限 `UnsupportedMedia`。

### 3.4 进程安全

- 复用 R3.5a：`Command::new().args([...])`，无 shell；
- `-nostdin -hide_banner -loglevel error`；
- `-protocol_whitelist file`；
- 15 分钟超时；stdout/stderr 1 MiB 上限；
- Windows `CREATE_NO_WINDOW`；
- 输出先写 `media/.tmp/<uuid>/`，`sync_all` 后 rename。

## 4. 转码与混音

### 4.1 左右视频

```text
ffmpeg -nostdin -hide_banner -loglevel error
  -protocol_whitelist file
  -i <source>
  -map 0:v:0 -an -sn -dn -map_metadata 0
  -c:v libx264 -preset veryfast -crf 20 -pix_fmt yuv420p
  -movflags +faststart -y left.mp4|right.mp4
```

说明：用户描述里的“H.264/AAC，暂时只保留视频轨”落地为 **H.264 视频轨、无音频轨**；音频统一由 `audio.wav` 承载，避免左右 mp4 各带一条无用音轨。

### 4.2 双声道 WAV

`stereo_audio_args` 使用 `filter_complex`：

- 输入：
  - `[0]` left 视频
  - `[1]` right 视频
  - `[2]` 左静音 `anullsrc`（仅左无音轨时使用）
  - `[3]` 右静音 `anullsrc`（仅右无音轨时使用）
- 左源：有音轨 `[0:a]`，无音轨 `[2:a]`
- 右源：有音轨 `[1:a]`，无音轨 `[3:a]`

每个源：

```text
aformat=sample_rates=48000:channel_layouts=mono
pan=mono|c0=c0
apad
atrim=duration=<commonDuration>
asetpts=PTS-STARTPTS
```

合并：

```text
[l][r]amerge=inputs=2
pan=stereo|c0=c0|c1=c1
```

输出：

```text
-c:a pcm_s16le -ar 48000 -ac 2 -t <commonDuration> audio.wav
```

- `commonDuration = max(left.durationMs, right.durationMs)`；
- 左视频无音轨时用 `anullsrc` 补零，右声道仍保留右视频音频；
- 左/右源音频都先 reset PTS 再合并，避免起始偏移；
- 硬 pan：左源只进 c0，右源只进 c1；不做左右串音。

实测结果（见测试）：

- 左无音轨 + 右 440Hz：`audio.wav` 左声道 max=0，右声道 max>0；
- 左 330Hz + 右无音轨：左声道 max>0，右声道 max=0。

## 5. manifest 数据结构

### 5.1 `MediaAsset` 扩展

新增可选字段（Rust / TS 都是 optional）：

```rust
pub stereo_pair_id: Option<String>,
pub eye: Option<String>,          // Left / Right
pub audio_channel: Option<String> // Stereo
```

三份资产：

| 文件 | kind | eye | audioChannel |
|---|---|---|---|
| `left.mp4` | Video | `Left` | null |
| `right.mp4` | Video | `Right` | null |
| `audio.wav` | Audio | null | `Stereo` |

三份资产共享 `stereoPairId`。

### 5.2 `StereoPair`

```rust
pub struct StereoPair {
    pub stereo_pair_id: String,
    pub left_asset_id: String,
    pub right_asset_id: String,
    pub audio_asset_id: String,
    pub created_at: i64,
}
```

`MediaManifest` 新增：

```rust
#[serde(default)]
pub stereo_pairs: Vec<StereoPair>,
```

- `schemaVersion` 仍为 1；旧 manifest 没有 `stereoPairs` 时按空数组加载；
- `load_manifest` 校验：
  - assetId 非空/唯一；
  - stereoPairId 非空/唯一；
  - pair 的 left/right/audio assetId 必须存在；
- `commit_stereo` 一次性 push 三份 asset + pair，最后一步原子写 manifest；失败时 truncate + 删除最终目录。

### 5.3 ID 与去重

- `stereoPairId = sha256(leftSourceSha256 + "|" + rightSourceSha256)[0..16]`；
- 正常 assetId = 存储文件 hash 前 16 位；
- 若 left/right 视频内容相同（或与既有 asset 碰撞），用
  `sha256(storedSha|pairId|side)[0..16]` 派生唯一 assetId；
- 因此同画面、不同音轨的左右视频也能成功落盘，不会因 assetId 碰撞报错；
- 入口先按左右 `sourceSha256` 查 `stereoPairs`；命中直接返回 `deduped=true`，不重复转码。

## 6. X 适配器

`v4/adapters/tauri/TauriMediaImporter.ts`：

```ts
async importStereo(leftPath: string, rightPath: string): Promise<MediaStereoImport>;
```

- 调用 command `media_import_stereo`，参数 `{ leftPath, rightPath }`；
- 错误统一转 `TauriInvokeError`，保留 `StereoDurationMismatch` / `StereoResolutionMismatch` 等 code；
- `importMono(...)` 标记 `@deprecated`，**不再 invoke**，直接抛：

```ts
new TauriInvokeError(
  'MonoImportDisabled',
  'single-eye media import is disabled; use importStereo(leftPath, rightPath)',
)
```

- `MediaStereoPair` / `MediaStereoImport` 是 X 层接口，不新增 A 类。

D 层 `MediaSource` 新增可选：

```ts
readonly stereoPairId?: string | null;
readonly eye?: 'Left' | 'Right' | null;
readonly audioChannel?: 'Left' | 'Right' | 'Stereo' | null;
```

## 9. 已知边界

1. 左右 mp4 只保留视频轨；音频统一在 `audio.wav`，符合“暂时只保留视频轨，音频单独抽”。
2. 源若为立体声，当前 `pan=mono|c0=c0` 取第一声道作为该眼的单声道源；如需整轨 downmix 可在 R3.5c 调整。
3. 同画面、不同音轨已通过 assetId salt 处理；若真实立体素材左右完全同画面，Q2 不拒绝，但 R3.5c 预览可能无 3D 效果。
4. `media_import` 的 D 层 `MediaImport` 类型保留，但命令已删除；X 的 `importMono` 仅用于显式报错。
5. 仍不支持导入后删除/GC；`stereoPairs` 只增。
6. 未改 E 层 `parallaxFactor`；R3.5c 负责同时挂载 left/right 并按关键帧偏移。
7. 未跑 app build（无 UI 改动）；Rust 与 v4 门禁/测试已跑。
