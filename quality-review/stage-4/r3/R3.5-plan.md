## 0. 结论（先看这一页）

1. **基线是绿的。** 2026-10-22 实测：`npm run verify:v4` 76/76 通过、四门禁 0 ERROR；`v4/app` typecheck / build 通过；`cargo test` 10/10 通过；ffmpeg / ffprobe 4.4.1 可用。
2. **默认建议编辑器 UI 放 X（`v4/app/src/screens/`），P 只保留入口。** P 可以通过 prop 接收 E 实例并调用方法（类型边允许），但 P 没有编辑器视图的 A 类名；新增 P 名要改 NAMEBOOK / TOTAL_A / stage-4 §3.1。默认选 X 是为了不动冻结契约；若你要求严格 P 层，走 D-1 的 B 方案（+3 个 P 名，+1–2d）。E 始终只提供纯视图模型，X 负责组合、Tauri 适配和路由。
3. **v2 保持“演出契约”，编辑器另存一份编辑文档。** `ChartSourceData v2` 只有 `chartId / provenance / layers / notes`，装不下 keyframe 稳定 ID、Logo、动效、媒体引用。建议 `charts/<chartId>.editor.json`（schema 1）作为编辑源，`charts/<chartId>.json` 作为显式导出的 v2。见 D-2。
4. **媒体走外部 ffmpeg 进程，不走 FFI。** 四个 command：`media_probe / media_import / media_trim / media_extract_frames`；输入用用户选择的绝对路径，输出只允许项目 `media/` 下的生成名；临时文件 + 原子 rename + manifest 最后写，失败清理。见 §4。
5. **关键帧拖拽是“预览态 / 提交态”两段式。** 拖动中只改 preview，不写历史；pointerup 一次性提交一个 `ChartEditUndo` 事务；Esc / pointercancel / 失焦全部回滚。见 §5。
6. **开工前必须先裁定三件事：D-1（UI 放哪层）、D-2（keyframe/Logo 存哪）、D-4（当前 fixture GUI 没有真实 project root 怎么办）。** 这三项决定文件结构、工期和是否要改冻结契约；其余风险有建议默认值。

## 2. 架构与数据契约

### 2.1 分层与命名边界（最重要的约束）

stage-4 §5 的矩阵：

- **P（presentation）**：值依赖只有 K；其他逻辑模块只能 `import type`。因此 P 不能 `new` E 的会话，也不能值导入 E 的枚举/静态方法；但 P 可以接收 X 传入的 E 实例，通过实例方法编辑（方法调用不需要值导入）。P 缺的是编辑器视图的 A 类名。
- **E（editor）**：值依赖 K / C / M；类型依赖 W / D / U / G；禁止 R / L / P。
- **D（media）**：值依赖 K；只放类型。
- **X（app/adapters）**：可以值依赖全部；Tauri 只在 X。

check-naming 的规则（`tools/check-naming-v4.cjs`）：

- `v4/core` 里每个 **export** 必须是 NAMEBOOK A 类且模块一致。
- A 类有、代码没实现，只统计，不报错。
- 所以 E 的内部类型（`EditorDocument`、`LogoGuide`、`DragState` 等）**不能 export**；跨文件共享要么放在同一个文件，要么挂到 A 类的字段/静态方法上，要么放 X。

NAMEBOOK §1.13 的 26 个 E 名额，本轮按下面映射用满，不新增：

| 概念 | 承载名 | 说明 |

- 加载时扫描已有 ID，counter 取最大后缀 + 1。
- 测试注入固定 `documentId`，结果确定。

### 2.2 数据模型

#### A. 编辑文档（`charts/<chartId>.editor.json`，schema 1）

字段：

- `schemaVersion`：1
- `documentId`：字符串，X 注入
- `chartId`：字符串
- `provenance`：`Mock` / `Midi`
- `layers`：`ChartLayer[]`（C 层类型：index / kind / fullScreenInput）
- `keyframes`：`ChartKeyframe[]`，按 timeMs、layer、id 排序
- `media`：`{ videoAssetId: string | null; audioAssetId: string | null }`
- `seed`：32 位非负整数（RandomSeed 的编辑侧载体）
- `updatedAt`：毫秒时间戳（X 注入）
- `editorVersion`：1

持久化只写这一个文件，保证一次原子写；`ChartSourceData v2` 是导出/导入格式，不是编辑源。这样避免“chart 写成功、logo 写失败”的双文件不一致。

#### B. `ChartKeyframe`

字段：

- `keyframeId`：稳定 ID
- `timeMs`：整数，0..duration
- `durationMs`：0 为 tap，>0 为 hold
- `chartLayerIndex`：1 基
- `gridCellId`：1..8，仅第 2 层
- `chartKeyId`：可选逻辑键
- `chartPadKind`：`Light` / `Heavy` / `TopMost`
- `logo`：可选，内联对象，不新增 A 名

`logo` 字段：

- `logoId`
- `assetId`：`builtin:head-logo` 或 `MediaSource.assetId`；默认 `builtin:head-logo`（随应用打包的 `head-logo.png`）
- `position`：归一化 `{ x, y }`，相对预览内容框（0..1）
- `size`：归一化高度（0.02..1）
- `stretch`：0.25..4
- `appearEffect` / `disappearEffect`：`None` / `FlashWhite` / `FlashBlack` / `Truncate` / `FadeDown` / `FadeUp` / `Strobe` / `Glitch`（与未来 C 层 `NoteLogoAppearance` / `NoteLogoDisappear` 对齐）
- `easing`：`Linear` / `EaseIn` / `EaseOut` / `EaseInOut`
- `tint`：可选 `NoteColor`

层规则（校验，不通过则拒绝提交并给诊断）：

- 第 1 层：`TopMost`，无 `gridCellId`。
- 第 2 层：`Heavy` / `Light`，必须有 `gridCellId`。
- 第 3+ 层：`Light`，无 `gridCellId`。
- `timeMs + durationMs <= duration`。
- 同一层同一时间允许多个 keyframe（和弦）；按 id 稳定排序。

起始/中间/结束不是存储字段，而是**按同一层的 timeMs 顺序派生**：首 = Start，末 = End，其余 = Middle。只有一个时同时是 Start/End。这样拖动/增删后角色自动正确，不需要维护冗余字段。

#### C. `ChartSourceData v2`

严格按 stage-4 §4.4：

- `schemaVersion`：2
- `chartId`
- `provenance`
- `layers`：`ChartLayer[]`
- `notes`：`MidiNoteEvent[]`

每个 note：

- `timeMs` / `durationMs`
- `chartLayerIndex`
- `gridCellId?`
- `chartKeyId?`
- `chartPadKind`

规则：

- 只接受 v2；v1 直接拒绝，诊断含 `UnsupportedSchemaVersion`。
- 顶层和 note 字段严格白名单；未知字段拒绝（避免 schema 漂移被静默吞掉）。
- `layers` 至少含第 1 层；index 唯一、从 1 连续；第 2 层可缺省（只有第 1 层时），若存在第 3+ 层则第 2 层必须存在。
- note 的层/Pad/格语义按上表校验。
- 按 timeMs、layer、grid、pad 稳定排序后返回冻结数组。
- 导出时由 `keyframes` 映射，不写 logo；`keyframes` 的稳定 ID 不进 v2。

#### D. 媒体类型（D 层）

`MediaSource`：

- `assetId` / `kind`（Video / Audio / Image / Depth）
- `displayName` / `relPath`
- `sha256` / `bytes`
- `durationMs` / `width` / `height` / `fps`
- `videoCodec` / `audioCodec` / `audioChannels` / `sampleRate`
- `createdAt`
- `derivedFrom`（assetId 或 null）
- `trim`（`{ startMs, endMs }` 或 null）

`MediaImport`：`{ asset, deduped }`
`MediaTrim`：`{ sourceAssetId, asset }`
`DepthMap`：`{ assetId, width, height, format }`
`DepthThreshold`：`{ near, far }`
`AudioSegment`：`{ assetId, startMs, endMs }`
`AudioMarker`：`{ timeMs, label }`
`Downbeat`：`{ timeMs, index }`

R3.5 只强依赖 `MediaSource` / `MediaImport` / `MediaTrim`；其他类型先落形状，避免 R4 再改契约。

`MediaProbe`（probe 返回）和 `MediaFrame`（抽帧返回）都不是 A 类名，放在 X 层 `TauriMediaImporter` 的返回类型里；Rust 侧同名结构不导出到 core。这样 D 层严格保持 8 个 A 名。

#### E. 视图模型

- `EditorTimeline`：`durationMs`、`viewStartMs`、`pxPerMs`、`tracks`、`clips`；提供 `timeAtX`、`xAtTime`、`snap`、`zoomAt`、`scrollBy`、`hitTest`。
- `EditorPlayhead`：`timeMs`、`playing`、`loop`；组合 `TimelineStateMachine`；`play/pause/seek/advance`。
- `EditorTrack`：`trackId`、`kind`（Rhythm / Media）、`label`、`layerIndex`、`keyframes`、`clips`。
- `EditorClip`：`clipId`、`assetId`、`startMs`、`durationMs`、`inMs`、`outMs`、`kind`；**派生视图，不落盘**。R3.5 每个媒体类型只有一个活动 clip（start=0），trim 结果切换活动 asset；多片段/移动留 R4。
- `EditorCanvas`：媒体、舞台宽高、fit、safe area、选中 Logo 矩形、picker 状态。
- `EditorInspector`：`build(selection, keyframes, mode)`；无选中返回 null；有选中返回字段描述 + 可用动作。
- `EditorSelection`：`selectedKeyframeId`、`hoveredKeyframeId`、`pickerActive`；本轮单选。

### 2.3 读写与保存

R3.5 一个 world 一个主谱面：`chartId` 默认等于 `worldId`；多谱面/谱面列表留 R4。

路径（相对 project root）：

- 编辑文档：`worlds/<worldId>/charts/<chartId>.editor.json`
- v2 导出：`worlds/<worldId>/charts/<chartId>.json`
- 媒体：`media/`；帧缓存：`media/frames/<assetId>/`
- manifest：`media/manifest.json`

加载顺序：

1. 进入编辑器时由 `EditorProjectFile` 解析目标 root 并显式 `project_open_root`；不依赖上一次的 active root。解析/打开失败 → D-4 的 dev fallback。
2. `project_ensure_layout`（已建 worlds/media/drafts）。
3. 读编辑文档；存在 → 严格 parse；损坏 → 只读诊断，不自动覆盖，提供“从 .bak 恢复 / 新建空文档”。
4. 不存在 → 读 v2；存在 → 导入为编辑文档（生成新 ID、无 logo）；不存在 → 新建空文档（layers 1/2）。
5. 读 `media/manifest.json`；缺失视为空；损坏 → 只读诊断，不写。

保存：

- `Ctrl+S` / 工具栏 Save：`EditorWorldFile.validate()` → 序列化 → `project_write_json_atomic` 一次写入；成功清 dirty。
- 退出时 dirty → 应用内三选一（Save / Discard / Cancel）；保存失败保持编辑器打开。
- `Export v2`：`EditorWorldFile.exportChartSource()` → `parseChartSourceData` 回读校验 → 写 `charts/<chartId>.json`；不写 logo。
- 导入 v2：`parseChartSourceData` → 新文档（新 ID、logo 为空）；若已有编辑文档，先确认替换。

#### 2.3.1 Project root 解析（D-4 默认方案）

1. 先试 `workspace_get_root`。成功且 `<workspaceRoot>/<folderId>/<projectId>` 存在 → 用。
   成功但目录不存在 → 只读诊断 `ProjectPathMissing`，**不回退 dev**（避免把内容写到错误项目）。
2. `workspace_get_root` 失败（当前 fixture 就是这种情况）→ 调 Rust 的 `project_ensure_dev_root(projectId)`：
   - Rust 只用 `app_data_dir()/neurou-dev/<projectId>`，**不接受任意绝对路径**；校验 projectId（8 位数字或安全 ID）；
   - `create_dir_all` → `canonicalize` → 设为 ActiveProjectRoot → allow `<root>/media`；
   - 返回绝对路径；
   - 前端再调 `project_ensure_layout` 建 `worlds/ media/ drafts/`；
   - 写 `dev-root.json` 标记（`schemaVersion` / `projectId` / `createdAt`），不伪造 `project.json`，避免被 ProjectStore 误认；
   - 编辑器顶部显示 `DEV PROJECT — <绝对路径>`，让验收者知道写在哪。
   注意：只有真实 workspace 未打开时才走这条；不要覆盖已有 workspace root。
3. 不修改 fixture workspace，不 materialize 项目树，不碰 `.trash`。
4. 真实 workspace 接线留 R4；R3.5 的证据必须标明“dev root”还是“真实项目”。

### 2.4 入口与路由

现状：`ProjectConsole` 的世界视图里按 `/` 打开一行命令输入，目前只处理 `exit/quit`（`WorldFolderConsole.tsx` 约 962 行）。R3.5 加法：

1. `ProjectConsoleProps` 增加两个可选 prop：
   - `onEnterEditor?: (world: WorldInstance) => void`
   - `editorActive?: boolean`
2. 世界命令行支持：
   - `edit`：若 `activeWorld` 存在且 `onEnterEditor` 存在 → 关闭命令行、调用回调；否则输出 `error: no world entered`。
   - `help`：输出 `edit / exit / quit`。
   - 未知命令：输出 `unknown command: x (try edit or exit)`，不再静默清空。
3. `editorActive` 为 true 时：
   - 世界 `keydown` 监听直接 return（不再响应 `/` / `Esc` / 方向键）。
   - React 的 `handleRootKeyDown` 也早退，防焦点回到 console 时方向键/Enter 穿透。

## 4. 问题 2：ffmpeg 接入与跨平台路径安全

### 4.1 接入方式

- **外部进程，不链接 FFI**：Rust `std::process::Command` 调 `ffmpeg` / `ffprobe`；不引入 `ffmpeg-next` / OpenCV。
- **二进制发现顺序**：
  1. 环境变量 `NEUROU_FFMPEG` / `NEUROU_FFPROBE`（测试/CI/用户覆盖）。
  2. 打包 sidecar：`resources/bin/<platform>-<arch>/ffmpeg[.exe]`（若存在）。
  3. PATH 上的 `ffmpeg` / `ffprobe`。
- **绝不接受 webview 传入的可执行文件路径**：避免 IPC 变成任意代码执行。只接受 env / sidecar / PATH。
- **版本检查**：启动或首次调用时跑 `-version`，要求主版本 >= 4.4；检查 `libx264` / `aac` 编码器；结果缓存。缺失 → `MediaToolMissing`，UI 显示安装提示，不崩溃。
- **参数数组，不拼 shell**：`Command::new(tool).args([...])`；Windows 加 `CREATE_NO_WINDOW`；`-nostdin -hide_banner -loglevel error`；`-protocol_whitelist file` 防 HLS/HTTP/`concat:` 拉流。
- **超时与输出上限**：probe 15s；trim 最长 15min 或 `max(60s, 4×duration)`；单帧 30s；总抽帧 120s。stdout/stderr 读取有上限（1 MiB），超限杀进程。超时 `ProcessTimeout`，清理临时目录。
- **并发**：`MediaLock(Mutex<()>)` 串行化 import/trim/frames；manifest 读改写也在锁内。
- **进度**：R3.5 先做 indeterminate spinner + 已用时间；ffmpeg `-progress pipe:1` 事件留 R4（避免第一版复杂化）。

### 4.2 命令契约

| 命令 | 输入 | 输出 | 失败码 |
|---|---|---|---|
| `media_probe` | `sourcePath`（绝对路径，用户选择） | `MediaProbe`（X 类型）：kind/duration/width/height/fps/codecs/audio | `MediaToolMissing` `ProbeFailed` `UnsupportedSourcePath` `ProbeOutputTooLarge` |
| `media_import` | `sourcePath`、`displayName?`、`kindHint?`（Auto/Video/Audio/Depth） | `MediaImport`：asset + deduped | `ProjectNotOpen` `MediaToolMissing` `UnsupportedMedia` `ImportRollback` `ManifestCorrupt` |
| `media_trim` | `assetId`、`startMs`、`endMs` | `MediaTrim`：sourceAssetId + 新 asset | `AssetNotFound` `InvalidTimeRange` `MediaToolMissing` `TrimFailed` `ManifestCorrupt` |
| `media_extract_frames` | `assetId`、`timesMs[]`、`maxWidth?` | `MediaFrame[]`：timeMs/relPath/width/height | `AssetNotFound` `InvalidTimeRange` `FrameLimitExceeded` `MediaToolMissing` `FrameFailed` |

约束：

- `timesMs`：1..120 个，整数，排序去重，0 <= t <= duration；越界 `InvalidTimeRange`。
- `maxWidth`：64..1920，偶数；不传保持原宽。
- `startMs < endMs`，且 end <= duration；最短 50ms；最长 30min。
- `media_trim` 只接受 Video / Audio；Image / Depth → `UnsupportedMedia`。
- `media_extract_frames` 只接受 Video；其他 → `UnsupportedMedia`。
- `kindHint=Depth` 只接受 PNG/JPG/JSON；不生成深度。**Depth JSON 不走 ffprobe**，由 `serde_json` 按 §4.2 的 schema 校验；PNG/JPG 可用 `image` 或 ffprobe 读尺寸。
- `media_probe` 对 Depth JSON 返回 `UnsupportedMedia`（UI 走 import 的深度入口）；`media_probe` 不需要 project root；其余三个需要。
- 所有输出路径由 Rust 生成，前端不传输出路径。

**编码 / 输出策略**

| 输入 | 输出 | 参数要点 |
|---|---|---|
| 视频（含音轨） | `.mp4` | H.264 (`libx264`, veryfast, CRF 20) + AAC 192k；`yuv420p`；`+faststart`；`-map_metadata 0` |
| 视频（无音轨） | `.mp4` | 同上 + `-an` |
| 音频（wav/flac） | `.wav` | PCM s16le；保留采样率/声道（上限 48kHz/2ch） |
| 音频（其他） | `.m4a` | AAC 192k；保留采样率/声道 |
| 抽帧 | `.jpg` | `-q:v 2`；等比缩放到 `maxWidth`；不放大 |

- 编码器缺失：`UnsupportedEncoder`，不静默换低质量编码器；UI 提示安装 full build。
- HDR / 10-bit / 非 4:2:0 源会转 8-bit `yuv420p`，可能有色偏；probe 记录源色彩信息，UI 提示。
- 旋转 Metadata 默认由 ffmpeg autorotate 处理；不手工转置。
- 深度 JSON 的最小 schema：`{ width, height, data: number[] }`，`data.length = width × height`，值域 0..1 或 0..65535，最大 4096×4096；不满足 → `UnsupportedMedia`。PNG/JPG 深度图接受 8/16-bit 灰度或 RGB。

### 4.3 路径安全

**输入路径（用户选择，允许在项目外）**

- `fs::canonicalize` 后必须是绝对路径、普通文件、非目录。
- 拒绝：空、NUL/换行、`\\.\` 设备路径、`\\?\GLOBALROOT`、`\\?\UNC\`；R3.5 对 UNC 网络路径给 `UnsupportedSourcePath`（避免 ffmpeg 长时间挂起），提示先复制到本地。
- 允许：Windows 盘符路径、macOS/Linux 绝对路径、中文/空格/前导 `-` 的文件名（canonicalize 后是绝对路径，作为单个 arg 传入）。
- 文件大小/时长上限：视频 4GB / 4h；音频 1GB / 4h；图片 64MB；超限 `UnsupportedMedia`。
- 扩展名只做提示，实际以 ffprobe 流为准；允许无扩展名。

**输出路径（只允许项目内）**

- 只接受项目相对路径；`Component` 只允许 `Normal`，拒绝 `RootDir` / `Prefix` / `ParentDir`；`\` 统一成 `/`。
- 最终 parent 必须存在或可创建；创建前对最近的已存在祖先 `canonicalize`，必须 `starts_with(project_root)`。
- 临时目录固定在 `media/.tmp/<uuid>/`；最终 rename 与临时文件同卷。
- 文件名由 Rust 生成：`<assetId>.<ext>`、`<assetId>-trim-<start>-<end>.<ext>`、`frames/<assetId>/<timeMs>.jpg`；不使用用户原始文件名做路径（只存 displayName）。
- Windows 保留名/尾点/ADS 不会出现，因为生成名是 hex + 数字；displayName 只用于 UI。
- 输出文件先写 temp，`sync_all`，rename；不直接写目标路径。

**进程参数**

- 所有路径用 `OsStr` / `PathBuf`，不经过字符串拼接。
- 探针：`ffprobe -v error -print_format json -show_format -show_streams`，`-show_entries` 限制字段；stdout 上限 1 MiB。
- 裁剪：`-ss <start> -i <src> -t <duration>`；先 `-ss` 快速定位，再精确重编码。
- 抽帧：`-ss <t> -i <src> -frames:v 1`；缩略图用快速 seek（±1 帧可接受）。
- 所有命令前加 `-protocol_whitelist file`；不启用 `concat` / `http` / `https` / `tcp`。
- 不设置 `current_dir` 到用户目录；用绝对路径，避免相对路径解析歧义。

**文件系统边界**

- 符号链接/junction：输出 parent 和目标都 canonicalize 后必须在 root 内；输入 canonicalize 解析到真实文件，允许用户选择 symlink。
- 大小写：Windows 上 `starts_with` 可能大小写敏感；root 和候选都 canonicalize 后比较；必要时 Windows 分支用大小写不敏感比较。
- 长路径：Rust std 支持 `\\?\`；不手工截断；错误信息保留可诊断路径。
- 磁盘满/权限失败：IO 错误 → 清理 temp → `ImportRollback`；不留下 manifest 条目。

### 4.4 失败回滚（逐阶段）

**import**

1. 源文件校验 → 失败：无写入。
2. 复制到 `media/.tmp/<uuid>.<ext>` → 失败：删 temp。
3. 对 temp 跑 ffprobe → 失败：删 temp。**Depth JSON 例外**：不跑 ffprobe，按 §4.2 的 JSON schema 校验；失败同样删 temp。
4. 流式 sha256 → 失败：删 temp。
5. 生成 assetId（hash 前 16 hex）；目标 `media/<assetId>.<ext>`：
   - 已存在且 hash 相同 → 去重，删 temp，返回已有 asset。
   - 已存在但 hash 不同 → 理论不可能（hash 命名），报 `AssetConflict`。
6. rename temp → 目标 → 失败：删 temp。
7. 读 manifest → 追加 asset → 原子写 → 失败：删除本次新目标（仅当不是去重），保留旧 manifest（`.bak` 不自动覆盖）。
8. 成功返回。

崩溃窗口：6 之后 7 之前会留下“有文件、无 manifest”的孤儿；加载时只报告，不自动删除、不自动登记。重复导入同一 hash 会去重并补登记。

**trim**

1. 读 manifest → 找 asset → 校验类型/时长/区间。
2. 输出 temp `media/.tmp/<uuid>.<ext>`。
3. ffmpeg 重编码 → 失败/超时：删 temp。
4. probe + hash → 失败：删 temp。
5. rename → manifest 原子写 → 失败：删新目标。
6. 返回新 asset；原 asset 不动。

**extract_frames**

1. 校验 asset/时间列表/上限。
2. 建 `media/frames/<assetId>/.tmp-<uuid>/`。
3. 逐帧 ffmpeg → 失败：删整个 batch 目录，返回错误（不保留半批）。
4. 全部成功 → rename 到 `media/frames/<assetId>/`；同名覆盖用临时名 + rename。
5. 不写 manifest；帧是缓存，可重建。

**manifest**

- `media/manifest.json` schema 1：`{ schemaVersion, assets[], updatedAt }`。
- Rust 拥有读写；TS 只读。
- 原子写复用 `fs.rs` 的 `write_json_atomic_at`（改成 `pub(crate)`），保留 `.bak`。
- 损坏：`ManifestCorrupt`，拒绝写入；UI 提示手动恢复 `.bak`，不静默重建。
- 并发：`MediaLock` 内完成“读 manifest → 写文件 → 写 manifest”。

### 4.5 跨平台与分发

- **Windows**：ffmpeg.exe/ffprobe.exe；`CREATE_NO_WINDOW`；盘符/长路径/中文路径测试；`ffmpeg` 4.4.1 已在 PATH。
- **macOS**：二进制名无 `.exe`；若未来沙盒/公证，sidecar 需签名；文件选择返回的路径在非沙盒下可直接读。
- **Linux**：发行版 ffmpeg 版本差异大；要求 >=4.4；AppImage 需自带或提示安装。
- **R3.5 分发策略**：开发/验收用系统 PATH + env 覆盖；不打包二进制。发布是否 sidecar 由 R5 决定（GPL 许可、体积、公证）。
- **许可**：当前 ffmpeg 是 GPL full build；若随应用分发，需满足 GPL 义务。计划文档记录，不在 R3.5 解决。

### 4.6 预览与 asset 协议

## 5. 问题 3：关键帧拖拽与数据更新逻辑

### 5.1 坐标与吸附

- 单一映射在 `EditorTimeline`：`timeMs = viewStartMs + (x - laneLeft) / pxPerMs`；反向 `x = laneLeft + (timeMs - viewStartMs) * pxPerMs`。
- 拖动时禁用缩放/滚动变更（或重新计算 anchor），避免“拖动中世界变了”。
- 吸附优先级：
  1. 视频帧边界（`1000 / fps`，fps 来自 probe；无视频则跳过）。
  2. 10ms 网格。
  3. `Alt` 临时关闭吸附。
- **加载 / 导入 v2 时保留原始 timeMs，不强制 10ms**；只有新增、拖动、Inspector 输入才吸附。避免 MIDI 来源的 1ms 精度被改写。
- `Shift` 锁定时间，只允许纵向换轨；`Ctrl` 不用于拖拽（避免与浏览器冲突）。
- clamp 到 `[0, duration]`；`duration` = max(媒体时长, 最后 keyframe + 1000, 10_000)。

### 5.2 拖拽状态机

```text
Idle
  │ pointerdown on marker（记录 id / startX / startY / 原 time / 原 layer / pointerId）
  ▼
Pressed（setPointerCapture；未写历史）
  │ 移动 > 3px 或 80ms
  ▼
Dragging（rAF 更新 dragPreview；显示时间 tooltip；自动滚动；更新 playhead）
  │ pointerup
  ▼
Commit（EditorWorldFile.moveKeyframe 一次；写一条 ChartEditUndo；清 preview）
```

取消路径：

- `Escape`、`pointercancel`、`lostpointercapture`、`window.blur` → 恢复原值，清 preview，不写历史。
- 拖动中如果 pointerup 没有位移 → 只选中，不写历史。

细节：

- **历史只在 drop 时写**，不在 dragstart 写；避免“按了没动也进 undo”。
- **拖动预览只影响被拖的 keyframe**；其他 keyframe 不重排，避免视觉跳动。drop 后统一排序。
- **纵向换轨**：指针进入另一条 lane 且纵向移动 > 24px 才切换，防抖；切换后：
  - 到第 1 层：pad=TopMost，清 grid。
  - 到第 2 层：pad 保持 Heavy/Light（默认 Light），grid 缺省 1。
  - 到第 3+ 层：pad=Light，清 grid。
- **同一层同一时间**允许多个 keyframe；drop 后按 time、id 稳定排序；不合并、不覆盖。
- **自动滚动**：拖到视口左右 8px 内，每帧滚 8–16px；滚动后重新计算 time，保证指针下时间连续。
- **性能**：dragPreview 用 ref + rAF，不每像素 setState；React 每帧最多一次；1000 keyframe 以内 DOM 可承受，超过则只渲染视口内 marker（R3.5 上限 1000，超出提示）。

### 5.3 数据更新与撤销

`EditorWorldFile.moveKeyframe(id, timeMs, layerIndex)`：

1. 找到 keyframe；不存在 → `KeyframeNotFound`。
2. 校验新时间/层/pad/grid；非法 → 返回诊断，不改文档。
3. 生成新对象（不原地改）；替换数组中对应项；排序。
4. `ChartEditUndo.record({ label: 'Move keyframe', before, after })`；超过 100 条丢最旧。
5. `EditorSelection` 保持选中 id；`dirty=true`；`version++`；通知订阅者。

undo/redo：

- `ChartEditUndo` 存 `before` / `after` 的 keyframe 快照 + 原索引；undo 恢复并重排；redo 再应用。
- 新编辑发生后截断 redo。
- 空操作（时间/层都没变）不记录。
- `Ctrl+Z` 在输入框内不拦截；在时间轴/预览区拦截。
- 删除 keyframe 的 undo 同时恢复 logo（同一个 patch）。

其他更新：

- Inspector 数字输入：Enter/blur 提交一次；非法回退并 toast。
- 滑块：`pointerdown` 记 before，`pointerup` 提交一次；拖动中只 preview。
- 选位：`LogoPositionPicker.commit` 写一次 `SetLogo`；拖动 Logo 的 drop 写一次 `MoveLogo`。
- 删除：`Delete/Backspace` 或右栏按钮；级联删 logo；一次 undo 恢复两者。
- 保存：不改文档，只清 dirty；undo 历史保留（保存后仍可 undo 到保存前，dirty 重新变 true）。

### 5.4 关键帧增删改与 Logo

- **新增**：双击 lane 空白；时间 = 吸附后的 x；层 = 该 lane；第 2 层默认 grid=1、pad=Light；第 1 层 pad=TopMost；第 3+ 层 pad=Light。新 keyframe 无 logo。
- **删除**：选中后 Delete；级联删 logo；undo 恢复。
- **移动**：见上；hold 的 duration 不变；若 `time+duration > duration`，clamp time 或提示。
- **改属性**：Inspector 编辑 time/layer/grid/pad/duration；每次提交一个 undo。
- **Logo 创建**：右栏“选位”→ 点击 stage → 若 keyframe.logo 为空则创建默认 logo（asset 默认 `builtin:head-logo`，size 0.18，position 点击点，easing EaseInOut）；已存在则只改 position。
- **Logo 随机**：`LogoRandomPlacement.place(seed, keyframeId, bounds)`；同 seed + 同 keyframe 顺序 → 同结果；按钮只改当前选中 keyframe；不批量覆盖已有 logo（避免破坏手摆）。
- **Logo 删除**：右栏“删除 Logo”只删 logo，保留 keyframe；删除 keyframe 则级联删 logo。
- **起始/中间/结束**：按同层 time 排序派生；Inspector 显示角色；第一个默认 appear、最后一个默认 disappear；中间默认参与插值。
- **动画**：`ChartKeyframeAnimation.sample(keyframes, t)`：
  - 只取有 logo 的 keyframe；无 → null。
  - 在相邻两个有 logo 的 keyframe 之间插值 position/size/stretch；easing 用前一个的。
  - 第一个之前/最后一个之后：隐藏（编辑器预览不模拟 lifetime；R4 运行时再实现 lead/lifetime）。
  - appear/disappear 只在首/末边界应用；中间不重复触发。
  - 只有单个 keyframe：静态显示，出现后保持。

### 5.5 测试点

- 时间↔像素：zoom/scroll 后往返误差 <0.5ms；边界 clamp。
- 吸附：10ms、帧边界、Alt 关闭；不同 fps。
- 拖拽：3px 阈值；Esc 取消；pointercancel；无位移不写历史；纵向 24px 换轨。
- 换轨：1/2/3+ 的 pad/grid 清理规则。
- 排序：同时间多 keyframe 稳定；undo 后顺序一致。
- undo：100 条上限；undo 后新编辑截断 redo；删除恢复 logo。
- 动画：start/mid/end 插值；单 keyframe；缺 logo；easing。
- 随机：同 seed 同 keyframe 结果一致；不同 seed 不同；bounds 内。
- Inspector：无选中 null；各模式字段；非法输入回退。
- 导出/导入：v2 round-trip；logo 不丢失（编辑文档）；v1 拒绝。
