## 2. 四个 Rust command 的实现要点

### 2.1 `media_probe`

- 输入：用户选择的绝对路径；只读，不需要 project root。
- 先做输入路径安全校验，再调 `ffprobe`：
  - `-v error -print_format json -show_format -show_streams`
  - `-protocol_whitelist file`
  - `-i <absolute path>`
- 解析：
  - `format.duration` / `format.size` / `format.format_name`
  - 首个 video stream 的 width/height/avg_frame_rate/r_frame_rate/codec_name
  - 首个 audio stream 的 codec_name/channels/sample_rate
- kind 判定：
  - 有 video + duration > 0 → `Video`
  - 只有 audio → `Audio`
  - 无 duration / image2 格式 / png/mjpeg/webp 等 → `Image`
- 失败码：`MediaToolMissing` / `ProbeFailed` / `UnsupportedSourcePath` / `OutputTooLarge`。
- 超时 15s；stdout/stderr 各 1 MiB 上限。

### 2.2 `media_import`

- 输入：`sourcePath`、可选 `displayName`、可选 `kindHint`（Auto / Video / Audio / Image / Depth）。
- 流程：
  1. 校验输入路径、大小上限（4 GiB 绝对上限；Video 4 GiB / Audio 1 GiB / Image+Depth 64 MiB）。
  2. 决定 kind：
     - Auto：ffprobe 结果；
     - Auto + `.json`：按深度 JSON schema 校验，不调 ffprobe；
     - 显式 hint：类型不匹配则 `UnsupportedMedia`。
  3. 计算源文件 SHA256；`assetId = sourceSha256[0..16]`。
  4. 去重：同 `sourceSha256 + kind` 且非派生资产 → 返回已有 asset，`deduped=true`。
  5. 输出格式：
     - Video：`.mp4`，H.264 (`libx264`, veryfast, CRF 20) + AAC 192k，`yuv420p`，`+faststart`，`-map 0:a:0?` 兼容无声视频；
     - Audio：源为 wav/flac → `.wav` PCM s16le；其他 → `.m4a` AAC 192k；
     - Image / Depth 图片：复制原文件，保留 png/jpg/jpeg/webp/bmp/tif/tiff；
     - Depth JSON：复制原文件，`.json`。
  6. 输出先写 `media/.tmp/<uuid>/asset.<ext>`；`sync_all` 后 rename 为 `media/<assetId>.<ext>`。
  7. 对输出重新 probe（视频/音频）或使用源 probe（图片/深度），写 asset：
     - `sha256` = 存储文件 hash；
     - `sourceSha256` = 源文件 hash（去重用）；
     - `derivedFrom=null`，`trim=null`。
  8. 最后一步原子写 manifest；失败删除本次 final 文件，旧 manifest 不动。
- 失败码：`MediaToolMissing` / `UnsupportedMedia` / `FfmpegFailed` / `ImportRollback` / `ManifestCorrupt` / `AssetConflict` / `InvalidKindHint`。
- 导入转码超时 15min；子进程 stdout/stderr 各 1 MiB 上限。

### 2.3 `media_trim`

- 输入：`assetId`、`startMs`、`endMs`。
- 校验：
  - `0 <= start < end <= duration`；
  - 最短 50ms；最长 30min；
  - 源 asset 必须是 Video / Audio。
- 精确切：`-ss <start> -i <source> -t <duration>`，重编码（不用 `-c copy`）。
- 输出格式与 import 一致（Video → mp4；Audio wav/m4a）。
- 输出新 asset：
  - `assetId = 输出文件 hash[0..16]`；
  - `derivedFrom = 源 assetId`；
  - `trim = { startMs, endMs }`；
  - 原 asset 不变。
- 同源同区间已存在 trim → 直接返回已有 asset（幂等）。
- 失败清理 temp/final，manifest 不变。

### 2.4 `media_extract_frames`

- 输入：`assetId`、`timesMs[]`、可选 `maxWidth`。
- 校验：
  - 1..120 个时间点；排序去重；0..duration；
  - `maxWidth` 64..1920 且偶数；
  - 源 asset 必须是 Video。
- 每帧：
  - `-ss <time> -i <source> -frames:v 1 -q:v 2`
  - 可选 `-vf scale=min(<maxWidth>\,iw):-2`
  - 输出 JPEG 到 `media/frames/<assetId>/<timeMs>.jpg`。
- 先写批量 temp 目录；全部成功后移动到最终目录；失败删除本次已移动帧，不动历史帧。
- **不写 manifest**；帧是缓存，可重建。
- 单帧超时 30s；最多 120 帧。

## 3. 路径与进程安全

### 3.1 输入路径（可位于项目外）

- 必须非空、绝对路径、长度 <=4096、无 NUL/换行。
- Windows 先拒绝原始 `\\.\`、`\\?\GLOBALROOT`、`\\?\UNC`；再 `canonicalize`，并再次检查解析后的 device/UNC 前缀。
- Unix 拒绝 `/dev/`、`/proc/`、`/sys/`。
- 必须是普通文件；拒绝目录、Windows 设备名（CON/NUL/COM1…）。
- 源文件不要求位于 project root 下（用户可自由选择）；读取由 ffmpeg/ffprobe 完成。

### 3.2 输出路径（只允许项目内）

- 只允许 `media/` 下的相对路径。
- 组件白名单：`CurDir` 跳过；`Normal` 拼接；**任何 `ParentDir` 直接 `InvalidPath`**；拒绝 `Prefix` / `RootDir`。
- `root.join("media")` canonicalize 后作为 media root；最终 candidate 必须 `starts_with(media_root)`。
- 最近已存在祖先 canonicalize 后必须仍在 project root 内，防 symlink/junction 逃逸。
- 文件名全部由 Rust 生成：`<assetId>.<ext>`、`<assetId>-...`、`frames/<assetId>/<time>.jpg`；用户原始文件名只进 `displayName`，不进路径。
- assetId 只允许 ASCII hex；扩展名只允许 alphanumeric；避免注入/特殊字符/尾点/ADS。

### 3.3 进程调用

- `Command::new(tool).args([...])`，**没有 shell 拼接**。
- 固定参数：`-nostdin -hide_banner -loglevel error`；所有输入前加 `-protocol_whitelist file`，禁止 HLS/HTTP/`concat:` 拉流。
- 二进制发现：
  - `NEUROU_FFMPEG` / `NEUROU_FFPROBE` 环境变量（必须是已存在文件）；
  - 否则 PATH 上的 `ffmpeg` / `ffprobe`；
  - **不接受 webview 传入的可执行文件路径**。
- 超时：
  - probe 15s；
  - trim / import 转码 15min；
  - 单帧 30s。
  - 超时 `child.kill()` + `wait()` + 清理 temp，错误码 `ProcessTimeout`。
- 输出上限：stdout/stderr 各 1 MiB；超限 `OutputTooLarge`，不把整段输出读进内存。
- Windows 使用 `CREATE_NO_WINDOW`，避免弹出控制台窗口。
- stderr 为空/非空都归一化为 `ProbeFailed` / `FfmpegFailed`，保留尾部诊断。

### 3.4 原子写与回滚

- 所有输出先写 `media/.tmp/<uuid>/`，同卷 rename 到最终路径。
- `sync_file` 在 Windows 上用 **可写句柄** 打开（只读 `File::open` + `sync_all` 会 `拒绝访问`，这是实测坑）。
- manifest 写入复用 `fs.rs` 的 `write_json_atomic_at`：temp + `sync_all` + `.bak` + rename。
- `MediaLock`（`Arc<Mutex<()>>`）串行化 import/trim/frames 及 manifest 读改写；probe 不加锁。
- `commit_asset` 是最后一步：
  - 先 push asset、写 manifest；
  - 失败时 pop，并删除本次 final 文件；
  - 旧 manifest/`.bak` 不动。
- 任意阶段失败都 `remove_dir_all(temp)`；import/trim 失败还会删除已 rename 的 final（`created_final` 跟踪）。
- 崩溃窗口：final 已存在、manifest 未写 → 孤儿文件；不自动删除，不静默登记；重复导入同 hash 可重新登记。

## 4. manifest v1

`media/manifest.json`：

- `schemaVersion: 1`
- `assets: MediaAsset[]`
- `updatedAt: number`

`MediaAsset` 字段（camelCase）：

- `assetId` / `kind` / `displayName` / `relPath`
- `sha256`（存储文件 hash）/ `sourceSha256`（源文件 hash，可选）
- `bytes` / `durationMs` / `width` / `height` / `fps`
- `videoCodec` / `audioCodec` / `audioChannels` / `sampleRate`
- `createdAt` / `derivedFrom` / `trim`

损坏策略：

- JSON 解析失败、`schemaVersion != 1`、assetId 为空/重复 → `ManifestCorrupt`；
- 拒绝写入，不静默重建；
- `.bak` 保留上一代，供人工恢复。

## 5. 跨平台 / ffmpeg 防坑

| 坑 | 处理 |
|---|---|
| Windows `canonicalize` 返回 `\\?\C:\...` | 允许本地盘符前缀；只拒绝 `\\?\UNC` / `\\?\GLOBALROOT` |
| UNC / 网络路径 | `UnsupportedSourcePath`，提示先复制到本地，避免 ffmpeg 卡住 |
| Windows 设备名 | `CON` / `NUL` / `COM1`… 拒绝 |
| 只读句柄 `sync_all` | 用 `OpenOptions::read(true).write(true)` |
| 控制台闪窗 | `CREATE_NO_WINDOW` |
| 空格 / 中文 / 前导 `-` 文件名 | 绝对路径作为单个 `OsString` 参数；不拼 shell |
| 误跟 HLS/HTTP | `-protocol_whitelist file` |
| 子进程卡死 | 硬超时 + kill + wait + 清理 temp |
| 输出打爆内存 | 1 MiB 上限，读线程超限后丢弃继续读，避免管道阻塞 |
| ffmpeg 缺失 | `MediaToolMissing`，不 panic；UI 后续显示安装提示 |
| 同名 final 冲突 | `AssetConflict`，不覆盖 |
| 转码失败 | `FfmpegFailed`；final 不落地，manifest 不变 |

环境实测：ffmpeg / ffprobe **4.4.1**，libx264/aac/pcm_s16le 可用。

## 8. 已知边界 / 后续

1. **没有进度与取消**：import/trim 只有超时；UI 阶段先做 spinner，ffmpeg `-progress` 留后续。
2. **没有版本探测**：要求 ffmpeg/ffprobe 可用（建议 >=4.4）；缺失返回 `MediaToolMissing`，不检测编码器列表。libx264/aac 缺失时真实命令失败 `FfmpegFailed`。
3. **没有 sidecar**：只支持 env / PATH；发布时是否打包 ffmpeg 由 R5 决定（GPL/体积/公证）。
4. **帧缓存覆盖**：同名时间点会替换旧帧；失败清理只针对本次移动的帧。
5. **没有 asset 删除/GC**：manifest 只增；孤儿文件只诊断，不自动清。
6. **manifest v1 无迁移**：后续加字段需保持 `schemaVersion=1` 兼容或升 v2。
7. **依赖 project root**：三个写命令要求先 `project_open_root`；编辑器 dev root 接线在 R3.5c/R3.5d。
8. **视频色彩**：HDR/10-bit 转 8-bit `yuv420p` 可能色偏；probe 保留源 codec，UI 可提示。
9. **Windows `sync_all`**：已改为可写句柄；跨平台文件系统（网络盘）未测试。
10. **命令权限**：`build.rs` 的 `APP_COMMANDS` 与 `capabilities/default.json` 都必须同时加；只改一处会 build 失败（已踩过）。
