## 1. 四个 DSH 决策

| 决策项 | 选择 | 理由 |
|---|---|---|
| Shift 状态变化是否走 ramp | **走 80ms 短 ramp**（`RAMP_SHIFT_MS`） | 高速推进时直接跳变会“顿一下”；80ms 足以平滑，又不会让 Shift 响应变钝 |
| RampingOut 期间重新按下 | **选项 A：从当前 speed 继续 RampingIn** | 避免速度先掉到 0 再上升的二次顿挫；保留缓出手感 |
| 到达边界时 | **不提前 RampingOut；保持 target，松开后正常缓出** | 边界由 `TimelineStateMachine.advance` clamp；提前减速会让“按住到边界”出现不必要的减速 |
| 曲线函数 | **easeInOutQuad** | 缓入/缓出两端都平滑，起步和收尾都没有线性折角；符合“克制、流畅”的手感 |

## 2. 参数

```ts
const INITIAL_STEP_MS = 50;
const BASE_PER_FRAME_MS = 8;
const RAMP_IN_MS = 150;
const RAMP_OUT_MS = 120;
const RAMP_SHIFT_MS = 80;
const SHIFT_MULTIPLIER = 3;
const FRAME_MS = 1000 / 60;
```

- `INITIAL_STEP_MS = 50`：保留补丁 4 的短按立即推进。
- `BASE_PER_FRAME_MS = 8`：以 60fps 为基准，目标速度约 480ms/秒。
- `RAMP_IN_MS = 150`：按住后 150ms 从 0 缓入到目标。
- `RAMP_OUT_MS = 120`：松开后 120ms 缓出到 0。
- `RAMP_SHIFT_MS = 80`：Shift 按下/松开时目标速度过渡。
- `SHIFT_MULTIPLIER = 3`：Shift + 左右约 3 倍速。
- `FRAME_MS = 1000/60`：按实际帧间隔缩放推进量。

速度单位是“每 60fps 帧推进多少 ms”；tick 中：

```text
advance(direction * currentSpeed * dt / FRAME_MS)
```

## 3. 速度状态机

内部维护：

```ts
type SpeedState = 'Idle' | 'RampingIn' | 'Steady' | 'RampingOut';
```

- `Idle`：speed = 0，无 rAF。
- `RampingIn`：从 `rampFrom` 到 `targetSpeed`，时长 150ms（Shift 变化为 80ms）。
- `Steady`：speed = targetSpeed。
- `RampingOut`：从松开瞬间的 `currentSpeed` 到 0（释放）或到较低 target（Shift 松开），时长 120ms / 80ms。

`easeInOutQuad`：

```ts
function easeInOutQuad(t: number): number {
  return t < 0.5 ? 2 * t * t : 1 - ((-2 * t + 2) ** 2) / 2;
}
```

关键点：

- `startSpeed` 取松开瞬间的 `currentSpeed`，不重置为 target，避免“突然加速一下再减速”。
- `RampingOut` 期间即使 `pressed` 为空，仍按 `lastDirection` 继续推进，直到速度衰减到 0。
- 双键同时按住时直接 `currentSpeed = 0`、`speedState = 'Idle'`、停止 rAF；不走 RampingOut。
- 从双键抵消中松开一键时，从 0 进入 RampingIn。
- 暂停时 rAF 可继续跑，但 `advance` 内部冻结；速度状态机不感知暂停，屏幕层不额外判断。
- 边界不提前减速；`advance` clamp，松开后正常缓出。

## 4. Shift 监听

使用 `event.code === 'ShiftLeft' | 'ShiftRight'`，而不是 `event.key`。

原因：浏览器 `KeyboardEvent.key` 对左右 Shift 都是 `"Shift"`；`code` 才是 `"ShiftLeft"` / `"ShiftRight"`。用 `event.code` 才能区分左右并符合监听要求。

- `shiftKeys: Set<'ShiftLeft' | 'ShiftRight'>`；
- Shift keydown 时若单方向按住，从当前速度 ramp 到新 target（80ms）；
- Shift keyup 对称处理；
- 两个 Shift 都按住时倍率仍只生效一次（Set size > 0）。

## 8. 人工验收清单

`tauri dev` → 视差演示：

1. **短按一下**：立即推进约 50ms，不是没反应。
2. **按住 150ms 内**：速度从 0 平滑增加，不出现突变。
3. **按住 150ms 后**：稳定在目标速度推进。
4. **松开**：速度平滑减到 0，约 120ms 内停止，不是瞬停。
5. **松开后立即重新按下**：从当前速度继续加速（选项 A），没有先掉到 0 的顿挫。
6. **同时按住左右**：互相抵消，速度归 0；画面不推进。
7. **松开一键**：从 0 缓入恢复单方向推进。
8. **Shift + 左右**：速度约 3 倍；Shift 按下/松开时有 80ms 平滑过渡。
9. **到 0 / 12000ms 边界**：停止推进；持续按住不越界。
10. **暂停时按住左右**：无推进；恢复播放后正常。
11. **卸载重进**：正常；无残留 rAF、按键或速度状态。
12. 三层视觉、视差框、HUD、target 切换保持正常。
