1.3 问题 2：v4/adapters/tauri/ 如何桥接逻辑层？

结论：选方案 A（Rust command 直接实现 fs 适配器），不启用 Node 后端，不以 plugin-fs 作为主写路径。

理由：
- Tauri 2 默认没有 Node 运行时，方案 B 不成立（除非引入 sidecar，复杂且破坏单机轻量目标）。
- plugin-fs 能读写文件，但不能保证 AC4-03 需要的 fsync + 原子 rename + .bak，也不能保证 AC4-11 的 NDJSON append + fsync；方案 C 会把关键语义交给权限插件，测试与审计都更弱。
- 方案 A 可以在 Rust 侧完整实现与 Node adapters 等价的 io 契约；Node adapters 保留给 headless 测试，Tauri adapters 作为同一端口的生产实现。
- plugin-dialog 只用于“选择文件/目录”对话框；实际读写仍走自定义 command。

桥接方式：
- 不改 ProjectStore / LedgerStore 的核心逻辑；它们接受 inline io。
- v4/adapters/tauri/ 新增：
  - TauriProjectIo：实现 ensureLayout / readProjectJson / writeProjectJson / readEventTreeJson / writeEventTreeJson，内部 invoke Rust command。
  - TauriLedgerFile：实现 readHead / readLines / appendLine / writeHead / hash，内部 invoke Rust command。
  - TauriMediaImporter：媒体导入/trim/抽帧的 command 封装（R3.5）。
  - tauriInvoke.ts：薄封装（invoke + 错误归一化）。
- Rust command（最小集）：
  - project_ensure_layout
  - project_read_json
  - project_write_json_atomic
  - ledger_read_head
  - ledger_read_lines
  - ledger_append_line
  - ledger_write_head
  - ledger_hash_sha256
  - media_probe / media_import / media_trim / media_extract_frames / media_extract_audio / depth_import_or_generate（R3.5）
- 路径安全：
  - Tauri 维护 ActiveProjectRoot state；
  - 所有 fs command 只接受相对路径；
  - Rust 侧 canonicalize 后必须落在 root 下；拒绝绝对路径、..、UNC、符号链接逃逸；
  - 项目未打开时 fs command 返回 ProjectNotOpen。
- 原子写：
  - Rust 写 .tmp → sync_all → 可选 .bak 字节复制 → rename → 清理 tmp；
  - 与 AtomicJsonFile 的四种崩溃语义一致（R3.3 接入时用 Tauri 侧集成测试验证；R3.1 只做骨架时可先不实现）。
- 账本：
  - Rust 追加 line + "\n" 后 sync_data；head 原子写；SHA-256 用 sha2；
  - 读写校验仍由 LedgerStore/LedgerReader 完成，Rust 只做字节层。

对既有 Node adapters 的处置：
- 保留，不删除；v4/tests 继续用 Node adapters 做 headless 测试。
- Tauri 与 Node 两套 io 必须共用同一组契约测试（R3.3/R3.5 增加 Tauri 集成测试；若 CI 无 Tauri 窗口，可用 command 层单测/无头调用）。

1.4 问题 3：EventTreeDAG / EventTreeDocument / EventTreeBuilder 最小实现

模块归属：G（v4/core/eventgraph/）。
R3 只落事件树数据层；EventGraph 运行时（AC4-20~22）留 R4。

A 类（5 个）：
- EventTreeNode
- EventTreeEdge
- EventTreeDAG
- EventTreeDocument
- EventTreeBuilder

数据结构建议：
- EventTreeNode：
  - nodeId: string
  - worldId: string（只存 worldId，不嵌入 WorldInstance）
  - position: { x: number; y: number }（DAG 画布布局，非世界坐标）
  - orphan: boolean（世界删除后标记；UI 灰显 + 警告图标）
  - 可选 entryAnchor?: { timelineMs: number; lateral: number }（进入该世界时的锚点；R3 只透传）
- EventTreeEdge：
  - edgeId: string
  - fromNodeId: string
  - toNodeId: string
- EventTreeDAG：
  - nodes: readonly EventTreeNode[]
  - edges: readonly EventTreeEdge[]
  - rootNodeId: string | null
- EventTreeDocument：
  - schemaVersion: 1
  - nodes / edges / rootNodeId
  - 与 R2 的 event-tree.json 占位完全同形：{ schemaVersion: 1, nodes: [], edges: [], rootNodeId: null }
  - 不新增 updatedAt（避免改 R2 ProjectStore 写入形状；文件 mtime 足够）

EventTreeBuilder 最小 API（无 React）：
- constructor(document?: EventTreeDocument)
- addNode(input) / removeNode(nodeId)
- addEdge(fromNodeId, toNodeId) / removeEdge(edgeId)
- setRoot(nodeId)
- renameNode?（R3 不需要）
- markOrphans(existingWorldIds: readonly string[])
- validate(existingWorldIds, worlds): Diagnostic[]
- toDocument(): EventTreeDocument
- build(): EventTreeDAG

校验：
- 节点 ID 唯一；边 ID 唯一；边端点存在；禁止自环。
- 环检测：Kahn 拓扑排序（或 DFS 三色）。有环 → 拒绝提交，返回 cycleNodeIds。
- 单根：入度为 0 的节点必须恰好 1 个；rootNodeId 必须指向该节点。
- 孤立节点：允许存在（没有边但仍有节点），但必须可达（从 root 可达）；不可达节点给 WARN/诊断，不静默删除。
- Primary 唯一性（AC4-06）：
  - 输入 worlds: readonly { worldId: string; kind: WorldKind }[]
  - 恰好一个 kind === WorldKind.Primary；
  - 该 worldId 必须等于 rootNodeId 指向节点的 worldId；
  - 否则拒绝。
- orphan（AC4-05）：
  - markOrphans(existingWorldIds) 只改 orphan 标记，不级联删除节点/边；
  - UI 灰显 + 警告图标；可从 DAG 手动删除；
  - 世界删除逻辑不在 G 内自动执行。

UI：
- P 新增 EventTreeView（React + SVG 边 + 绝对定位节点）。
- 支持新增/删除节点与边、选择、右键菜单（R3.2 最小交互）。
- orphan 节点灰显 + 警告；删除按钮可用。
- 不做完整 EventGraph 蓝图运行时。

1.6 问题 5：视差渲染（PixiJS）与逻辑层解耦

数据层（W，R3.4 新增 8 个 A 类）：
- VisualFrame、VisualFrameRect、VisualFrameParallaxFactor、VisualFrameSaturation、GlobalSaturation、FrameTarget、FrameTracking、VisualFrameTargetLock。

建议语义：
- VisualFrameRect：屏幕矩形 { x, y, width, height }。
- VisualFrameParallaxFactor：每层视差因子（number；由 W 数据提供）。
- VisualFrame：矩形 + 每层因子 + FrameTarget + FrameTracking + VisualFrameTargetLock + 只读饱和度。
- FrameTarget：目标点/目标框（屏幕坐标）。
- FrameTracking：Tracked / Lost / Locked（或等价枚举）。
- VisualFrameTargetLock：Locked / Unlocked。
- VisualFrameSaturation / GlobalSaturation：只读 number；逻辑层不读取渲染颜色。
- 逻辑层不 import Pixi；P 只读 W 数据。

P（PixiJS）：
- ParallaxRenderer：创建/管理 PIXI.Application 或 Container；读取 WorldInstance.layers（至少 3 层）；渲染前景/中景/背景。
- ParallaxCamera：根据 timeline progress / lateral 计算相机偏移；不写 W。
- ForegroundUV / MidgroundUV / BackgroundUV：三层 UV/偏移值对象；由 renderer 使用。
- 渲染输入：只读 WorldInstance + Layer + VisualFrame + TimelineProgress 快照。
- 三层视差与时间轴同步：
  - R3 用 requestAnimationFrame + TimelineStateMachine 的 progress；
  - 每层 offset = progress * layer.parallaxFactor（具体公式在 P 内，可配置）；
  - 不做音频时钟（AudioOutputClock 留 R4）。
- 左右移动（AC4-08）：
  - 键盘/指针输入 → TimelineStateMachine.seek/advance；
  - 边界 clamp；暂停冻结；
  - W 只提供数据与边界，P 处理输入。
- 视差框（AC4-09）：
  - W 计算 target in frame / FrameTracking / lock；
  - P 画矩形与饱和度；
  - 逻辑层不读取渲染颜色。

TimelineStateMachine：
- R2 是 interface；R3.4 建议升级为同名 class（A 类不变），补 play/pause/seek/advance/progress、方向、边界。
- 这会改 R2 文件 v4/core/timeline/types.ts；需 P-R3-05 批准。

1.8 问题 7：媒体导入（AC4-23）的 Tauri/Rust 接口

D（media 类型）：
- MediaSource：assetId / kind / durationMs / width / height / fps / audioStreams / path。
- MediaImport：源路径、目标路径、assetId、hash、probe 结果、状态。
- MediaTrim：源 assetId、startMs、endMs、输出 assetId/path。
- DepthMap / DepthThreshold：R3 只做类型 + 导入（图片/JSON 深度图）；SGBM 生成留 R4/R5。
- AudioSegment / AudioMarker / Downbeat：R3 只做音频导入/切段所需最小字段；完整音乐工程留 R4。

Tauri commands：
- media_probe(path) → MediaSource（ffprobe JSON）
- media_import(projectRoot, sourcePath, targetName?) → MediaImport（复制到 media/，hash，probe，失败回滚）
- media_trim(assetId, startMs, endMs) → MediaTrim（ffmpeg -ss/-to；输出新 asset）
- media_extract_frames(assetId, times[]) → string[]（ffmpeg 抽帧到 media/frames/）
- media_extract_audio(assetId) → AudioSegment（ffmpeg -vn）
- depth_import_or_generate(assetId) → DepthMap：R3 只支持导入深度图；生成返回 Unsupported（明确 diagnostic，不伪造深度图）

实现：
- 调用系统 ffmpeg/ffprobe（已确认 4.4.1 可用），不链接 ffmpeg-next/OpenCV；Rust 用 std::process::Command。
- 失败回滚：先写 temp 目录/临时文件 → probe/trim 成功 → 原子 rename 到 media/；任一步失败清理 temp，不产生半成品。
- 路径安全：同 fs command，仅项目相对路径；源文件路径由 dialog 选择后传入，Rust 读取前校验。
- SGBM：R3 不实现；depth_generate 返回 Unsupported；R4/R5 再评估 OpenCV/own SGBM。
- Rust 依赖（R3.5 增加）：sha2、hex、uuid、image、thiserror；ffmpeg 作为外部运行时依赖写入 README/验收。
- 前置：ffmpeg 缺失时 command 返回 MediaToolMissing，UI 显示可诊断错误；不崩溃。

5. 风险点与缓解
================================================================================

R3-R1 工具链/网络：Tauri CLI、npm 包、cargo crates 需要首次下载；可能受网络/镜像影响。
- 缓解：R3.1 单独做安装验证；失败则停在 R3.1，不进入业务代码；记录 lockfile。

R3-R2 Node/Tauri 双适配器漂移：同一 io 契约两套实现，原子写/账本可能不一致。
- 缓解：契约测试双跑；R3.3 加 Tauri command 层集成测试；Rust 实现逐条对照 AC4-03/11/12。

R3-R3 路径逃逸：自定义 fs command 可被传入任意路径。
- 缓解：ActiveProjectRoot + canonicalize + 相对路径白名单 + 拒绝 .. / 绝对路径 / UNC；Rust 单测覆盖。

R3-R4 P 门禁误伤：check-zero-engine 若继续扫描 presentation，会因 React/Pixi 报 ERROR。
- 缓解：R3.2 先改扫描范围并加 selftest；P 目录明确排除；K~R 仍全扫。

R3-R5 Primary 世界数据源：project.json 只有 worldIds，没有 kind；AC4-06 需要 WorldKind。
- 缓解：ProjectStore 增加只读 world summaries（读 worlds/<id>/world.json）；在 R3.2 前定契约（P-R3-06）。

R3-R6 TimelineStateMachine interface→class：会改 R2 文件，可能影响现有类型。
- 缓解：同名 A 类；只补行为不改名称；R3.4 前由 PROTOCOL 批准；加回归测试。

R3-R7 EventTreeView 交互复杂度：DAG 拖拽/连线/环检测 UI 容易超 R3.2。
- 缓解：R3.2 只做最小增删/选择/灰显；拖拽布局可简化为固定网格/绝对坐标；完整编辑器留 R4。

R3-R8 媒体子进程：ffmpeg 参数/编码/路径空格/中文路径；失败回滚。
- 缓解：统一 Command 参数数组（不经 shell）；临时目录；probe 后再发布；错误码可诊断；ffmpeg 缺失显式提示。

R3-R9 app 与根 CJS/TS 冲突：根 tsconfig/package 不应被 app 污染。
- 缓解：v4/app 独立 package/tsconfig；根 npm scripts 不改；Vite alias 读取 ../core；server.fs.allow 显式配置。

R3-R10 stage-4.v1.1 不一致：当前工作区未见补遗，provisional 未固定。
- 缓解：R3.1 前确认落盘；未确认不把 provisional 改 false；P-R3-01 阻断。

R3-R11 console 键盘焦点/可访问性：cmd 风格 + 上下键 + 右键 + 预览点击。
- 缓解：WorldFolderConsole 统一键盘事件；输入框聚焦时不让全局键抢占；R3.3 测试覆盖。

R3-R12 AC4-34 范围膨胀：右栏 6 条交互 + keyframe 动画 + logo 选位 + undo。
