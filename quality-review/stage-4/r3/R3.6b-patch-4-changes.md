## 1. Application 长驻方案

### 旧行为

`ProjectTreeView` 的 effect 依赖 `[workspace, worldThemes]`。双击空白创建 Folder 后：

1. workspace state 更新；
2. effect cleanup → `app.destroy()`；
3. 新 effect → 重新 `Application.init()`。

即使已解绑 filter、`texture:false`，频繁 destroy/init 仍可能命中 Pixi 8 TexturePool / BindGroup 的时序问题。

### 新行为

- `appRef = useRef<PIXI.Application | null>(null)`；
- 初始化 effect 依赖 **`[]`**：
  - 首次 mount 时 `new PIXI.Application()` + `init()`；
  - `appRef.current = app`；
  - 真正 unmount 时才 destroy。
- `workspaceRef` / `worldThemesRef` 保存最新数据；
- `syncSceneRef.current = rebuildScene`；
- 单独的 `useEffect([workspace, worldThemes])` 只调用 `syncSceneRef.current?.()`。

`rebuildScene()`：

1. `nodeLayer.removeChildren()`；
2. `nodeViews.clear()`；
3. `backgroundLayer.removeChildren()`；
4. `currentBackground = null`、`nextBackground = null`、缓存 key 清空；
5. `edgeGraphics.clear()`；
6. 用 `workspaceRef.current` 重新创建节点；
7. 重新设置背景。

**不销毁 Application、不销毁 filter、不销毁 texture。**

这样可以做到：

- 双击后新增 Folder 时，旧 app 与 fisheye filter 保持存活；
- 新节点直接增量重建到同一个 stage；
- 画面不会黑屏；
- 控制台不再出现 `textureSource destroyed while still bound to a shader`。

### StrictMode

- 初始化 effect cleanup：`appRef.current = null`、`syncSceneRef.current = null`，再 destroy；
- async mount 的 `disposed` 分支直接销毁未挂载的 app；
- 第二次 mount 重新创建，不会同时存在两个实例。

## 2. 纹理销毁逻辑

- 删除所有显式 `texture.destroy()`；
- 删除 `textureCache.clear()` / `imageCache.clear()`；
- cache 是 effect 局部 Map，离开作用域交给 GC；
- cleanup 只做：
  1. `app.ticker.remove(update)`；
  2. `detachFilters(app.stage)`；
  3. `app.stage.removeChildren()`；
  4. `app.destroy(false, { children: true, texture: false, textureSource: false })`；
- 不在数据变化时执行 destroy。

---

## 3. 保留项

- DOM 全屏放大；
- 新涟漪；
- Folder 0.65 尺寸；
- 外部降亮；
- 3D 布局 / 相机 / 游走；
- 非放大状态 Fisheye。

同时把 zoom 的 data URL 从 WebP 改为 **PNG**，并加纯色背景兜底，避免 WebView2 对 Canvas WebP 支持差异导致放大层透明。
